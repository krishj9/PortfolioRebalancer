Standard Protocols

Agent-to-Agent (A2A) & Model Context Protocol (MCP)

Decoupled agent microservices communicating over standard industry protocols, preventing vendor lock-in and enabling polyglot agent ecosystems.

Autonomous Micro-Agent Execution
The Research Agent runs as an independent A2A service at :8101/a2a/research. It ingests the portfolio context envelope, performs model synthesis, and returns structured regime insights without exposing internal state.
• Decoupled scaling & independent deployment
• Standardized task correlation envelope (`request_id`, `task`, `symbols`)
• High throughput async HTTP execution with client timeouts
// A2A Request Envelope { "task": "portfolio_research", "request_id": "req_9a4f21", "symbols": ["EQUITY", "BONDS", "CASH"], "portfolio_request": { ... } } // A2A Structured Response { "protocol": "A2A", "summary": "Macro conditions warrant rebalancing...", "payload": { "regime": "VOLATILE", "confidence": 0.85 } }
Anthropic MCP JSON-RPC 2.0 Standard
The Sentiment MCP Server runs at :8201/mcp, exposing standard tool discovery (tools/list) and tool execution (tools/call). Any MCP-compliant client can orchestrate it seamlessly.
• Dynamic tool schema negotiation at runtime
• Standardized JSON-RPC error codes and payload schemas
• Reusable across LangGraph, Claude Desktop, and Gemini Agent Engine
// MCP tools/call Payload { "jsonrpc": "2.0", "id": "sentiment-check", "method": "tools/call", "params": { "name": "analyze_symbol_news_sentiment", "arguments": { "symbols": ["EQUITY", "BONDS"] } } } // MCP Result Output { "result": { "sentiment": "CAUTIOUS", "score": -0.10 } }
Zero-Downtime Fallback Circuit Breakers
If remote network calls to A2A or MCP servers time out or fail, the supervisor gracefully engages in-process deterministic fallbacks. The system never halts or enters an unrecoverable failure state.
• Stage results explicitly tag execution_location: "in_process_fallback"
• UI displays protocol origin indicators for 100% transparency
• Circuit breakers reset automatically upon service restoration
# Resilience Circuit Breaker in Orchestrator try: stage, data = await self._run_remote(request) except (httpx.HTTPError, ValueError): logger.warning("A2A remote failed. Using in-process fallback.") stage, data = self._run_local(request) # Workflow State set to DEGRADED without blocking human review state.workflow_state = "DEGRADED"
Perimeter Defense

Google Cloud Armor: Edge WAF & DDoS Protection

First line of defense: Attached to the Global External Application Load Balancer to inspect HTTP/S traffic, throttle malicious IPs, and block OWASP Top 10 exploits before packets ever reach Cloud Run.

🛡️
Preconfigured OWASP CRS
Enforces preconfigured ModSecurity Core Rule Sets (CRS v3.3): SQL Injection (sqli-v33-stable), Cross-Site Scripting (xss-v33-stable), and Local File Inclusion (lfi-v33-stable).
DENY(403) PERIMETER BLOCK
⚡
Adaptive Rate Limiting
Throttles traffic at 120 requests/minute per client IP using SRC_IPS_V1. Prevents automated brute-force attacks, scraping, and denial of service without impacting genuine advisors.
THROTTLE · 120 REQ/MIN
🔑
Identity-Aware Proxy (IAP)
Sits behind Cloud Armor on the HTTPS backend service. Validates Google corporate credentials via OIDC and securely passes x-goog-authenticated-user-email for RBAC authorization.
ZERO TRUST INGRESS
# Terraform Cloud Armor Policy Definition (infra/gcp/terraform/edge.tf) resource "google_compute_security_policy" "edge_security_policy" { name = "${var.app_name}-edge-armor" description = "Cloud Armor edge security policy with OWASP mitigations & rate limiting" # SQLi & XSS Preconfigured Rules rule { action = "deny(403)" priority = 1000 match { expr { expression = "evaluatePreconfiguredExpr('sqli-v33-stable')" } } } # IP Rate Limiting rule { action = "throttle" priority = 2000 match { versioned_expr = "SRC_IPS_V1" config { src_ip_ranges = ["*"] } } rate_limit_options { conform_action = "allow" exceed_action = "deny(429)" rate_limit_threshold { count = 120 interval_sec = 60 } } } }
Generative AI Guardrail

Google Cloud Model Armor: GenAI Threat Mitigation

Proactive LLM defense: Sanitizes free-form advisor notes, detects prompt injection & jailbreak exploits, suppresses trade recommendation generation, and enforces a fail-closed architecture.

🛑
Prompt Injection Screening
Model Armor template (rebalancer-content-safety) inspects user inputs for role hijacking, system instruction overrides, delimiter escapes, and malicious URIs in BLOCK enforcement mode.
ENFORCEMENT = BLOCK
🔒
Fail-Closed Orchestration
When a threat is detected, LangGraph transitions to workflow_state="BLOCKED". Proposal generation is halted, and cryptographic approval tokens (apr_...) are strictly suppressed.
APPROVAL SUPPRESSION
📊
Security Telemetry & Alerts
Emits high-priority CONTENT_BLOCKED audit events to Cloud Logging and BigQuery analytics. SRE dashboards track incidents via the content_blocked_count metric.
CLOUD MONITORING METRIC

Context & Memory

Memory Architecture: Multi-Tiered Context Management

Long-term contextual memory provides personalized advice without runaway prompt token costs, security leakage, or stale preferences.

🗄️
User-Scoped Memory Bank
Memories are partitioned strictly by `user_id`. One investor's ESG preferences or risk aversion never bleed into another account's graph execution.
TENANT ISOLATION
⚡
Top-5 Capping & Truncation
Dynamic hydration caps memories to the top-5 most relevant facts and truncates each to 1,000 characters. Prevents prompt bloat and maintains low latency.
TOKEN BUDGET OPTIMIZATION
🔄
Async Post-Approval Ingestion
Memory generation runs asynchronously in background threads upon human approval. The user receives immediate response without waiting for memory extraction.
ZERO LATENCY PENALTY
Contradiction Detection
When new portfolio targets contradict historical memories (e.g. asking for aggressive growth after recording extreme risk aversion), the memory agent flags the conflict directly in the recommendation package.
Full CRUD & Preference Reversion
Advisors can inspect all stored memories via GET /api/memory and permanently revoke outdated preferences via DELETE /api/memory/{id}, restoring baseline neutrality.

Human-in-the-Loop

Cryptographic Approval State Machine

Zero Autonomous Trade Execution: AI agents produce decision-support packages, but trades can never be placed without explicit, non-repudiable advisor authorization.

Approval Lifecycle & Security Guards
1. Proposal Generation: Agents formulate trade actions and package with calculated drift and policy verdicts.

2. Cryptographic Binding: The payload is hashed with SHA-256 and locked into an approval artifact with deterministic ID (`apr_...`).

3. Stale Proposal Guard: When the advisor clicks "Approve", the server re-verifies `expected_recommendation_hash`. If market ticks altered the portfolio in the meantime, the stale approval is rejected.

4. Audit Event Persistence: Accepted transitions record immutable events in the audit table with user identity and timestamp.
